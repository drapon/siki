# siki 操作系 CLI 設計ヒアリング記録

**作成日**: 2026-06-30
**ヒアリング実施**: 設計フェーズ（フル設計）の差分ヒアリング

## ヒアリング目的

要件定義（軽量版）と実コード調査をもとに、設計レベルで実装が分岐する点
（プロセスモデル・引数パース方式・対話 UI）を確定するためのヒアリングを実施した。

## 質問と回答

### Q1: 設計の作業規模

**カテゴリ**: スコープ
**背景**: 薄い CLI ラッパで設計骨子は実装プランで固まっている。

**回答**: **フル設計**

**信頼性への影響**: architecture.md / dataflow.md / interfaces.rs / 本記録を作成。
DB スキーマ・API エンドポイントは CLI のため非生成と確定。

---

### Q2: `siki run` のプロセスモデル

**カテゴリ**: アーキテクチャ
**背景**: exec 置換（siki を claude に置き換え）か、status 待機（siki が親として残る）か。

**回答**: **exec で置換（推奨）**

**信頼性への影響**: アーキテクチャに「exec 置換／対話セレクタは exec 前に完結し raw mode 解除」を確定（🔵）。
unix 専用前提のため移植性問題なしを確認。

---

### Q3: サブコマンドの引数パース（初回）

**カテゴリ**: 技術選択
**背景**: 手書き継続 / clap 導入などの選択。

**回答（初回）**: 手書き継続（推奨）。**ただし後で再検討の申し出あり（Q5 へ）**。

---

### Q4: `siki run` の対話フォールバック（ユーザー発案）

**カテゴリ**: アーキテクチャ / UX
**背景**: ユーザーより「引数を全部書けばその通り動くのは合意。`siki run` だけのときは
選択肢や入力欄を出しながら進めるのが良いのでは」との提案。

**回答**: **2モード方式を採用**。引数が揃えば宣言モードで非対話実行、不足分のみ対話で補完。

**信頼性への影響**:
- 設計の中心方針として確定（🔵）。位置引数を必須にしない設計に変更。
- この結果、clap の主利点（必須引数の自動エラー・--help 自動生成）が薄れ、Q5 の判断に影響。
- `path` / `list` はスクリプト連携のため非対話を維持（stdout を汚さない）と確定。

---

### Q5: 引数パース（再検討の結論）

**カテゴリ**: 技術選択
**背景**: Q4 の対話フォールバック採用を踏まえ、4案（手書き毎／手書き＋共有ヘルパ／lexopt／clap）を再比較。
依存ツリーに既存のパーサは無く、いずれも新規追加が必要であることも確認。

**回答**: **手書き＋小さな共有ヘルパ（ArgScan、0依存）**

**信頼性への影響**: `src/cli/args.rs` に値フラグ・`--` 丸投げの検証を集約する設計を確定（🔵）。
clap は不採用（対話化で利点が薄れ、新依存＋既存ディスパッチ全面移行のコストに見合わない）。

---

### Q6: 対話セレクタの見た目

**カテゴリ**: UX
**背景**: 矢印キーTUI型 / 番号入力メニュー型。

**回答**: **矢印キーTUI型（推奨）**

**信頼性への影響**: `src/cli/prompt.rs` を crossterm（既存依存）で実装、`select_one`/`input_line`/`confirm`
を定義（🔵）。siki 本体と見た目が揃う。

---

### Q7: 対話フォールバックの対象コマンド

**カテゴリ**: スコープ
**背景**: run のみ / run+new+rm / path 以外全部。

**回答**: **run / new / rm**

**信頼性への影響**: 3コマンドに対話補完を実装、`path`/`list` は非対話と確定（🔵）。
`rm` には削除確認（`confirm`）を入れる。

---

## ヒアリング結果サマリー

### 確認できた事項
- フル設計、出力は architecture/dataflow/interfaces.rs/design-interview の4点（DB・API は非該当）
- `run` は exec 置換。対話セレクタは exec 前に完結し raw mode を解除
- broker 非起動でも DB 直書きで状態復元可能

### 設計方針の決定事項
- **2モード方式**（宣言／対話フォールバック）を設計の中心に据える
- 引数パースは **手書き＋共有ヘルパ ArgScan（0依存）**。clap 不採用
- 対話 UI は **矢印キーTUI型**（crossterm、新依存なし）
- 対話対象は **run / new / rm**、`path`/`list` は非対話
- `resolve_base_branch` を `config.rs` へ移設して main/cli 共有

### 残課題
- プロジェクト名解決は完全一致で仮置き（REQ-403, 🟡）。運用感を見て prefix 許容を再検討可。
- 対話中 Esc 中止時の exit code（0 / 非0）は実装時に統一する。

### 信頼性レベル分布

**ヒアリング前**（要件のみ）:
- 🔵 青信号: 5
- 🟡 黄信号: 4
- 🔴 赤信号: 2（exec方式・パース方式・対話有無が未定）

**ヒアリング後**:
- 🔵 青信号: 11（+6）
- 🟡 黄信号: 2（-2）
- 🔴 赤信号: 0（-2）

# PRヘッダー強化 設計ヒアリング記録

**作成日**: 2026-06-23
**ヒアリング実施**: kairo-design step4（既存情報ベースの差分ヒアリング）

## ヒアリング目的

設計フェーズで残るアーキテクチャ・データモデル・技術選択の不明点を明確化するためのヒアリング。

## 結論: 追加ヒアリングは実施せず（理由を以下に記録）

本要件の**ユーザー向け設計判断は要件フェーズ（kairo-requirements step4）で全5問確定済み**であり、
設計フェーズで新たに発生する判断は内部実装に閉じ、確定要件から一意に導出できるため、
追加のユーザーヒアリングは不要と判断した。

### 要件フェーズで確定済みの判断（再掲）

| 論点 | 確定内容 | 反映先 |
|------|----------|--------|
| 状態色の優先順位 | CIエラー最優先 → approved → draft → ready | `classify_pr_status` の判定順序 |
| 番号フォーマット | `タイトル #123`（後置き） | `render_branch_header` の表示文字列 |
| CI 進行中(pending) | 通常状態扱い（赤にしない） | 失敗系のみ CiError、pending は通常判定 |
| クリック範囲 | PR 部分のみ | `pr_link_area` のヒットテスト範囲 |
| 取得鮮度 | 既存3トリガーのみ | 取得タイミング据え置き（ポーリング無し） |

### 設計フェーズで設計者判断とした内部事項（ヒアリング不要）

| 設計判断 | 採用 | 根拠（信頼性） |
|----------|------|----------------|
| PR 情報の保持形式 | `Worktree.pr: Option<PrInfo>`（struct に集約） | 単一責任・既存 `pr_title` の自然な拡張 🔵 |
| 状態判定の構造 | I/O と分離した純粋関数 `classify_pr_status` | テスト容易性・受け入れ基準の検証 🔵 |
| クリック領域の保持 | `App.pr_link_area: Option<Rect>` | 既存 `claude_content_area` と同パターン 🔵 |
| 色変換の置き場所 | `main_panel.rs`（描画層）で `PrStatus`→`Color` | 関心の分離（app.rs を ratatui 非依存に保つ）🔵 |
| ブラウザ起動 | `std::process::Command` + `cfg(target_os)` で OS 別 | 新規 crate を増やさない 🟡 |
| JSON パース | 既存依存 `serde_json` | Cargo.toml:21 に存在 🔵 |

## 設計方針の決定事項

- 既存の単方向データフロー（取得→イベント→状態→描画）を踏襲し、新規レイヤを追加しない
- `PrInfo` はイミュータブルに扱い、再取得時は値を丸ごと置換
- `gh` 失敗・PR 無しは従来通り `None` に縮退

## 残課題

- **非フォーカス時の状態色反映可否**: 既存挙動（全体 DarkGray 化）を踏襲（REQ-402, 🟡）。
  実装・レビュー時に最終確認する
- **ブラウザ起動失敗時の通知**: `show_info` で軽く通知する想定（UI はブロックしない）。
  文言は実装時に既存の通知文言に合わせる

## 信頼性レベル分布

**設計フェーズ前**:
- 🔵 青信号: 5（要件確定事項）
- 🟡 黄信号: 1（非フォーカス時挙動）
- 🔴 赤信号: 0

**設計フェーズ後**:
- 🔵 青信号: 多数（内部設計判断が確定）(+)
- 🟡 黄信号: 2（多OSブラウザ起動 / 非フォーカス時グレー化）
- 🔴 赤信号: 0

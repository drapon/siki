# PRヘッダー強化 ヒアリング記録

**作成日**: 2026-06-23
**ヒアリング実施**: 計画フェーズ + kairo-requirements step4（既存情報ベースの差分ヒアリング）

## ヒアリング目的

中央ペイン PR ヘッダーの拡張にあたり、既存実装（`render_branch_header` / `fetch_pr_title`）
を調査したうえで、表示仕様・状態判定・操作仕様の曖昧点を明確化するためヒアリングを実施した。

## 質問と回答

### Q1: 状態色の優先順位（複数状態が同時成立する場合）

**カテゴリ**: 未定義部分詳細化
**背景**: approved だが CI 失敗、draft かつ CI 失敗 等で色が競合するため、優先順位の確定が必要だった
**回答**: **CIエラー最優先(赤)**。次に approved=緑 → draft=グレー → ready=イエロー

**信頼性への影響**:
- REQ-002 の優先順位を 🔴 → 🔵 に確定

---

### Q2: CI ステータスの取得鮮度

**カテゴリ**: 既存設計確認
**背景**: CI は時間で変わるが、現状 PR 取得は3トリガー（起動時 / Claudeセッション完了後 /
worktree追加時）のみ。定期ポーリングの要否を確認する必要があった
**回答**: **既存タイミングのみ**（定期ポーリング追加なし）

**信頼性への影響**:
- REQ-401（取得タイミングの制約）を 🔵 に確定。実装スコープを最小化

---

### Q3: PR 番号の表示フォーマット・配置

**カテゴリ**: 未定義部分詳細化
**背景**: `#123 タイトル`（前置き）か `タイトル #123`（後置き）か、表示順を確定する必要があった
**回答**: **`タイトル #123`**（タイトルの後ろに番号）

**信頼性への影響**:
- REQ-001 の表示フォーマットを 🔴 → 🔵 に確定

---

### Q4: CI 進行中(pending/running) の色

**カテゴリ**: 未定義部分詳細化
**背景**: CI チェックが進行中（成否未確定）のとき赤にするか、通常状態とするかを確認する必要があった
**回答**: **通常状態で表示**（赤にしない。失敗系のみ赤、それ以外は approved/draft/ready の通常判定）

**信頼性への影響**:
- REQ-002 の pending 仕様を 🔵 に確定

---

### Q5: クリックでブラウザを開く反応範囲

**カテゴリ**: 未定義部分詳細化
**背景**: ヘッダー行全体をクリック対象にするか、PR 部分のみにするかを確定する必要があった
**回答**: **PR 部分のみ**（`タイトル #123` の文字範囲のみ反応。ブランチ名部分は反応しない）

**信頼性への影響**:
- REQ-003 のクリック範囲を 🔴 → 🔵 に確定

---

## ヒアリング結果サマリー

### 確認できた事項
- 表示フォーマット（`タイトル #123`）
- 状態色と優先順位（CIエラー最優先 → approved → draft → ready）
- CI 進行中(pending) は通常状態扱い
- クリック反応範囲は PR 部分のみ
- PR 情報取得は既存3トリガーのみ（定期ポーリングなし）

### 追加/変更要件
- 既存 `pr_title: Option<String>` を拡張し、番号・URL・状態を保持する構造へ変更（REQ-001/002/003）
- クリック→ブラウザ起動の新規動線を追加（REQ-003）

### 残課題
- 非フォーカス時の状態色反映可否は明示確認せず既存挙動（全体グレー化）を踏襲（REQ-402, 🟡）。
  実装時に最終判断する

### 信頼性レベル分布

**ヒアリング前**:
- 🔵 青信号: 0
- 🟡 黄信号: 1（REQ-402 相当）
- 🔴 赤信号: 4（表示形式・色優先・pending・クリック範囲）

**ヒアリング後**:
- 🔵 青信号: 5（REQ-001/002/003/401/403）(+5)
- 🟡 黄信号: 1（REQ-402）(±0)
- 🔴 赤信号: 0（-4）

**品質評価**: 高品質（主要要件はすべてヒアリングで確定）

## エピック1: worktree削除後もタブが壊れない

### ストーリー 1.1: 開いているタブが固まらない 🔵

**信頼性**: 🔵 *ユーザー実環境での再現報告（`指揮者` 削除で `toronto` が操作不能）より*

**私は** siki を使う開発者 **として**
**あるプロジェクト内の1つの worktree を削除した後も、別の既に開いている worktree の
Claude タブ／ターミナルタブを閉じずにそのまま使い続けたい**
**そうすることで** 無関係な worktree の作業を、削除操作のたびに中断されずに済む

**関連要件**: REQ-003, REQ-004, REQ-005

**詳細シナリオ**:
1. プロジェクト内に4つの worktree（0:cmux, 1:エージェント, 2:指揮者, 3:toronto）があり、
   `toronto` の Claude タブを開いて作業している
2. `指揮者`（worktree_index=2）を削除する
3. `reindex_worktree_maps` により `toronto` の HashMap キーが `(pi,3)`→`(pi,2)` にシフトする
4. `toronto` の Claude タブでは、既に起動済みの PTY 読み取りスレッドが引き続き出力イベントを
   送っており、id 一致の再探索によって新しいキーの実体へ正しく届き続け、画面が更新され続ける

**前提条件**:
- 同一プロジェクト内に3つ以上の worktree があり、削除対象より後ろの worktree でタブを
  開いて操作中である

**制約事項**:
- REQ-401 により、実際にタブが閉じられた後の遅延イベントは引き続き黙って破棄される

**優先度**: Must Have

### ストーリー 1.2: 別worktreeの内容が混入しない 🟡

**信頼性**: 🟡 *コード調査 (`app.rs:611-627`) から妥当な推測。実発生の目撃は未確認*

**私は** siki を使う開発者 **として**
**あるworktreeを削除しても、別のworktreeのチャット履歴やターミナル画面に無関係な内容が
紛れ込まないことを保証したい**
**そうすることで** Claude との会話履歴やターミナル出力を安心して参照できる

**関連要件**: REQ-002, REQ-006

**詳細シナリオ**:
1. `send_to_claude` 経由で worktree A の `ClaudeSession` がストリーミング中に、worktree A
   より前の worktree が削除され、A の worktree_index がシフトする
2. `ClaudeSession` の読み取りタスクは古い `worktree_id` のまま出力イベントを送り続ける
3. `id` 一致による再探索で「現在 A の `ClaudeSession` が保存されているキー」を特定し、
   そのキーで `app.worktree_by_id_mut` を呼ぶため、シフト後に偶然そのキーへ来た**別の
   実在 worktree** へ誤って書き込まれることがない

**前提条件**:
- `send_to_claude` によるヘッドレス Claude セッションが動作中に、同一プロジェクト内で
  worktree 削除が発生する

**優先度**: Must Have

## エピック2: プロジェクト削除の健全性

### ストーリー 2.1: プロジェクト削除後も他プロジェクトが正常動作する 🔵

**信頼性**: 🔵 *コード調査 (`main.rs:4417-4483`) で確認した未実装箇所（Bug C）より*

**私は** siki を使う開発者 **として**
**登録している複数プロジェクトのうち1つを除外（削除）した後も、残りのプロジェクトの
セッション・ターミナルが正しく動作し続けることを期待する**
**そうすることで** プロジェクト整理のたびに他プロジェクトの作業に支障が出ることを防げる

**関連要件**: REQ-102, REQ-103

**詳細シナリオ**:
1. `siki`, `api`, `web` という3プロジェクトが登録されており、`api`（project_index=1）を
   削除する
2. `web`（project_index=2 → 1 へシフト）で動作中のセッション・ターミナルが、新設の
   `reindex_project_maps` によって `sessions`/`terminals`/`claude_terms` のキーを
   正しく引き継ぐ
3. `selected_worktree` が `web` を指していた場合も `project_index` が正しく補正される

**前提条件**:
- 3つ以上のプロジェクトが登録されており、末尾以外のプロジェクトを削除する

**優先度**: Must Have

## エピック3: 再発防止

### ストーリー 3.1: 回帰テストによる保証 🔵

**信頼性**: 🔵 *ヒアリングで再発防止テストの実施を確定*

**私は** siki のメンテナ **として**
**今回のようなインデックスずれ不具合が将来のリファクタリングで再発しないことを
ユニットテストで保証したい**
**そうすることで** 安心して `main.rs`/`terminal.rs`/`claude.rs` の関連コードを変更できる

**関連要件**: REQ-003, REQ-004, REQ-005, REQ-006, REQ-101, REQ-102

**詳細シナリオ**:
1. worktree 削除・プロジェクト削除それぞれについて、reindex 前後で `sessions`/
   `terminals`/`claude_terms` のキーが期待通りシフトすることを検証するテストを追加する
2. id ベースの再探索ヘルパーについて、worktree_id/tab_index がシフトした状態でも
   `terminal_id` 一致で正しいキーを返すことを検証するテストを追加する

**優先度**: Should Have

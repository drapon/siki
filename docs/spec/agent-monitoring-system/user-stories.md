## エピック1: エージェント活動の俯瞰

### ストーリー 1.1: プロジェクト単位でエージェントの活動を見る 🔵

**信頼性**: 🔵 *ユーザヒアリング 2026-06-19（スコープ=両方, トリガー=m）*

**私は** 複数の worktree で並行作業させている siki 利用者 **として**
**左ペインで気になるプロジェクトを選び `m` キーでそのプロジェクトのエージェント活動ポップアップを開きたい**
**そうすることで** そのプロジェクト内の各 worktree のエージェントが今/直前に何をしているかを一目で把握できる

**関連要件**: REQ-003, REQ-005, REQ-106

**詳細シナリオ**:
1. 左ペインでプロジェクト行（または配下の worktree 行）にカーソルを合わせる
2. `m` を押す
3. 中央にポップアップが開き、当該プロジェクトの worktree ごとにエージェント行（activity・summary・role・state・経過時間）が表示される
4. `Esc` で閉じる

**前提条件**:
- 対象プロジェクトに 1 つ以上の worktree が存在する
- broker が稼働しセッション状態を収集できている

**制約事項**:
- トリガーキーは既存キーと衝突しない `m` を使用する（REQ-003）
- 表示中は他ペインのキー操作を横取りする（REQ-201）

**優先度**: Must Have

### ストーリー 1.2: 全プロジェクトを横断して全体を把握する 🔵

**信頼性**: 🔵 *ユーザヒアリング 2026-06-19（「全体でエージェントの動きを把握する箇所がない」）, 2026-06-22（M / 状態優先順）*

**私は** 多数のプロジェクト・worktree を抱える siki 利用者 **として**
**`M` キーで全プロジェクト横断のダッシュボードを開きたい**
**そうすることで** 今どこで誰が動いているか・止まっているかを1画面で俯瞰できる

**関連要件**: REQ-004, REQ-005, REQ-006

**詳細シナリオ**:
1. 任意の状態で `M`（Shift+m）を押す
2. 全プロジェクト → worktree → エージェントの活動が、状態優先順（waiting > working > done > idle）で一覧表示される
3. 要対応（waiting）・稼働中（working）が上位に来る
4. `Esc` で閉じる

**前提条件**:
- 1 つ以上のセッションが登録されている

**優先度**: Must Have

## エピック2: リアルタイム性と「何をしているか」の解像度

### ストーリー 2.1: ツール単位で活動内容を知る 🔵

**信頼性**: 🔵 *ユーザヒアリング 2026-06-19（粒度=レベルB）*

**私は** エージェントの進捗を細かく確認したい利用者 **として**
**各エージェントが実行中/直前のツール（例:「Bash: bun test」「Edit: session.rs」）を見たい**
**そうすることで** 「working」という状態だけでなく具体的に何の作業中かを判断できる

**関連要件**: REQ-001, REQ-002, REQ-102, EDGE-001, EDGE-002

**詳細シナリオ**:
1. エージェントが PreToolUse hook を発火（ツール実行開始）
2. siki が tool_name/tool_input から activity 文字列を生成・保持
3. 監視ビューに activity が表示される

**前提条件**:
- worktree の `.claude/settings.json` に hook が注入済み

**優先度**: Must Have

### ストーリー 2.2: 開いている画面が自動で更新される 🔵

**信頼性**: 🔵 *コードベース調査（broker → AppEvent::SessionUpdate、100ms Tick）*

**私は** 監視ビューを開いたままにしておきたい利用者 **として**
**画面を開いている間、状態や activity の変化が自動で反映されてほしい**
**そうすることで** 手動でリロードせずに進捗を眺め続けられる

**関連要件**: REQ-101, NFR-001, NFR-002

**詳細シナリオ**:
1. 監視ビューを開いたままにする
2. いずれかのセッションが状態遷移（working↔waiting↔done 等）
3. broker が `AppEvent::SessionUpdate` を送出、TUI が 1 秒未満で再描画
4. ビューの該当行が更新される

**優先度**: Must Have

---

### ストーリー 2.3: 完了後も直前の活動が残る 🔵

**信頼性**: 🔵 *ユーザヒアリング 2026-06-22（activity=直前を残す）*

**私は** 一段落したエージェントの直近の作業を確認したい利用者 **として**
**ツール完了（PostToolUse）や停止（Stop）後も、直前に何をしていたかを見たい**
**そうすることで** 完了/待機に入ったエージェントが「最後に何をしたか」を追える

**関連要件**: REQ-103

**優先度**: Should Have

## エピック3: 人間の介入が必要な状況の発見

### ストーリー 3.1: 要対応のエージェントが目立つ 🔵

**信頼性**: 🔵 *ユーザヒアリング 2026-06-22（alert強調）, `session.rs` alert 機構*

**私は** 多数のエージェントを並行で回す利用者 **として**
**許可待ち（waiting）や set_alert が立ったエージェントを赤系で強調表示してほしい**
**そうすることで** 自分の操作・判断を待っているエージェントを即座に見つけて対応できる

**関連要件**: REQ-104, REQ-006

**詳細シナリオ**:
1. あるエージェントが PermissionRequest（waiting）または set_alert を発生
2. 監視ビューで該当行が赤系で強調表示される
3. ダッシュボードでは状態優先順で上位に並ぶ

**優先度**: Must Have

---

### ストーリー 3.2: アクティブなエージェントが居ないことが分かる 🟡

**信頼性**: 🟡 *UX 上の妥当な推測*

**私は** 利用者 **として**
**対象にアクティブなエージェントが居ないとき、その旨のメッセージを見たい**
**そうすることで** 空表示が「壊れているのか」「単に居ないのか」を迷わない

**関連要件**: REQ-202

**優先度**: Should Have

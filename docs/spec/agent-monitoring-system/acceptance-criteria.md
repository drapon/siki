## REQ-001 / REQ-002 / REQ-102: ツール活動（activity）の取得・保持 🔵

**信頼性**: 🔵 *ヒアリング（粒度=レベルB）・`hook_event.rs`*

### Given（前提条件）
- worktree に hook が注入済みで broker が稼働している
- あるセッションが PreToolUse hook を発火する

### When（実行条件）
- `siki hook-event working` が tool_name/tool_input を含む stdin を受け取る

### Then（期待結果）
- 該当セッションの activity が、生成された人間可読文字列に更新される
- activity が SessionRegistry（インメモリ）と sessions テーブル（SQLite）の両方に保持される

### テストケース

#### 正常系

- [ ] **TC-001-01**: Bash ツールの activity 生成 🔵
  - **入力**: `{"session_id":"s1","tool_name":"Bash","tool_input":{"command":"bun test","description":"テスト実行"}}`
  - **期待結果**: activity が「Bash: テスト実行」（description 優先）または「Bash: bun test」になる
  - **信頼性**: 🔵 *ヒアリング例示より*

- [ ] **TC-001-02**: Edit ツールの activity 生成 🔵
  - **入力**: `{"session_id":"s1","tool_name":"Edit","tool_input":{"file_path":"/x/src/session.rs"}}`
  - **期待結果**: activity が「Edit: session.rs」（ベース名）になる
  - **信頼性**: 🔵 *ヒアリング例示より*

- [ ] **TC-001-03**: working 受信で registry と DB の activity が更新される 🔵
  - **入力**: working イベント（activity 付き）を broker に送信
  - **期待結果**: `SessionRegistry` の該当 Session.activity と sessions テーブルの activity 列が一致して更新される
  - **信頼性**: 🔵 *`broker.rs:149` sync_to_db 経路*

#### 異常系

- [ ] **TC-001-E01**: tool_input にキーが無い場合 🟡 *EDGE-001*
  - **入力**: `{"session_id":"s1","tool_name":"Foo","tool_input":{}}`
  - **期待結果**: activity が「Foo」（tool_name のみ）になる。エラーにならない
  - **信頼性**: 🟡 *payload 多様性からの推測*

- [ ] **TC-001-E02**: tool_input 値に改行・制御文字 🟡 *EDGE-002*
  - **入力**: `command` に `"a\nb\tc"` を含む
  - **期待結果**: 1 行に正規化（改行・タブ除去/置換）された activity になる
  - **信頼性**: 🟡 *表示崩れ防止の推測*

#### 境界値

- [ ] **TC-001-B01**: activity が optional で後方互換 🔵 *REQ-401*
  - **入力**: activity フィールドの無い従来形式 `{"event":"working","session_id":"s1"}`
  - **期待結果**: serde でデシリアライズが成功し、activity は None（既存挙動を破壊しない）
  - **信頼性**: 🔵 *note.md・後方互換要件*

## REQ-401 / REQ-402 / REQ-403: 互換性・マイグレーション・タイムアウト制約 🔵

**信頼性**: 🔵 *`hook_event.rs`・`db.rs`*

### Given（前提条件）
- 既存の sessions テーブルと既存 hook 経路が稼働している

### When（実行条件）
- 新バージョンを既存 DB に対して起動する / 従来形式の working イベントを受信する

### Then（期待結果）
- activity カラムが冪等な ALTER TABLE で追加され、既存行は activity=NULL のまま維持される
- 既存形式イベントも引き続き処理される

### テストケース

#### 正常系

- [ ] **TC-401-01**: 既存 DB へのマイグレーション 🔵
  - **入力**: activity カラムの無い旧 sessions テーブルを持つ DB で `db::init` を実行
  - **期待結果**: activity カラムが追加され、再実行してもエラーにならない（冪等）
  - **信頼性**: 🔵 *`db.rs:49-60` の既存パターン踏襲*

- [ ] **TC-401-02**: serde 後方互換テスト 🔵
  - **入力**: `VALID_HOOK_STATES` 各状態の従来形式 JSON
  - **期待結果**: 全状態が `HookEvent` にデシリアライズできる（既存 `test_valid_hook_states_deserialize` を破壊しない）
  - **信頼性**: 🔵 *`session.rs:600` 既存テスト*

#### 境界値

- [ ] **TC-403-01**: hook タイムアウト予算 🔵
  - **測定**: activity 抽出を含む `siki hook-event working` の所要が、stdin(1s)+broker タイムアウト合計 < 5s に収まる
  - **信頼性**: 🔵 *`hook_event.rs:9-23`*

## REQ-003 / REQ-106 / REQ-201: プロジェクト別ポップアップ 🔵

**信頼性**: 🔵 *ヒアリング（m）・既存ポップアップパターン*

### Given（前提条件）
- 左ペインにプロジェクト/worktree ツリーが表示されている
- 対象プロジェクトに 1 つ以上のアクティブセッションがある

### When（実行条件）
- プロジェクト行または配下 worktree 行にカーソルを置いて `m` を押す

### Then（期待結果）
- 当該プロジェクトのエージェント活動ポップアップが開く
- 表示中は他ペインの通常キーが横取りされ、`Esc` で閉じる

### テストケース

#### 正常系

- [ ] **TC-003-01**: プロジェクト行で `m` → ポップアップ表示 🔵
  - **入力**: プロジェクト行で `m`
  - **期待結果**: そのプロジェクトの worktree 群とエージェント行が表示される
  - **信頼性**: 🔵 *ヒアリング*

- [ ] **TC-003-02**: worktree 行で `m` → 所属プロジェクトのポップアップ 🟡 *REQ-106*
  - **入力**: worktree 行で `m`
  - **期待結果**: その worktree が属するプロジェクトのポップアップが開く
  - **信頼性**: 🟡 *UX 上の妥当な推測*

- [ ] **TC-003-03**: `Esc` で閉じる 🔵
  - **入力**: ポップアップ表示中に `Esc`
  - **期待結果**: ポップアップが閉じ、通常操作に戻る
  - **信頼性**: 🔵 *REQ-105 既存パターン*

#### 異常系

- [ ] **TC-003-E01**: アクティブなエージェント不在 🟡 *REQ-202*
  - **入力**: セッションの無いプロジェクトで `m`
  - **期待結果**: 「アクティブなエージェントなし」メッセージを表示
  - **信頼性**: 🟡 *UX 上の妥当な推測*

#### 境界値

- [ ] **TC-003-B01**: 同一 worktree に複数セッション 🔵 *EDGE-101*
  - **入力**: 同一 worktree に 2 セッション存在
  - **期待結果**: 2 行が個別に表示される
  - **信頼性**: 🔵 *`by_worktree` 複数返却*

## REQ-004 / REQ-006: 全体ダッシュボード 🔵

**信頼性**: 🔵 *ヒアリング（M / 状態優先順）*

### Given（前提条件）
- 複数プロジェクト・worktree にまたがるセッションが登録されている

### When（実行条件）
- 任意の状態で `M`（Shift+m）を押す

### Then（期待結果）
- 全セッションが状態優先順（waiting > working > done > idle）で一覧表示される

### テストケース

#### 正常系

- [ ] **TC-004-01**: `M` で全体ダッシュボード表示 🔵
  - **入力**: `M`
  - **期待結果**: 全プロジェクトのエージェントが1画面に表示される
  - **信頼性**: 🔵 *ヒアリング*

- [ ] **TC-004-02**: 状態優先順のソート 🔵
  - **入力**: waiting / working / done / idle の混在セッション
  - **期待結果**: waiting → working → done → idle の順に並ぶ
  - **信頼性**: 🔵 *ヒアリング・`SessionState::priority()`*

#### 境界値

- [ ] **TC-004-B01**: 表示行数超過時のスクロール 🟡 *EDGE-103 / REQ-301*
  - **入力**: 表示領域を超えるセッション数
  - **期待結果**: スクロール/ページングで全件閲覧できる
  - **信頼性**: 🟡 *項目数次第・design で具体化*

- [ ] **TC-004-B02**: unknown セッションの扱い 🟡 *EDGE-003*
  - **入力**: cwd 空で自動登録された "unknown/unknown" セッション
  - **期待結果**: design で定めた方針（表示 or 抑制）どおりに扱う
  - **信頼性**: 🟡 *design フェーズで確定*

### 1. `WorktreeMeta.parent` フィールド追加（`src/config.rs`） 🔵

**信頼性**: 🔵 *architecture.md セクション2、実地確認（`src/config.rs:341-346`）より*

現状の `WorktreeMeta`（`src/config.rs:341-346`）は以下の通り、`display_name` 1フィールドのみを持つ：

```rust
#[derive(Debug, Clone, Deserialize, Serialize)]
pub struct WorktreeMeta {
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub display_name: Option<String>,
}
```

これに、既存フィールドと**全く同じ** `#[serde(default, skip_serializing_if = "Option::is_none")]` 属性パターンで `parent` を追加する：

```rust
#[derive(Debug, Clone, Deserialize, Serialize)]
pub struct WorktreeMeta {
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub display_name: Option<String>,
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub parent: Option<String>, // 🔵 REQ-010: 同一project内の親worktree名。Noneは独立worktree
}
```

`#[serde(default, ...)]` により、`parent` キーが存在しない旧形式の `project.json` を読み込んでも `None` にデシリアライズされ、後方互換性が保たれる 🔵 *design-interview.md訂正なし、既存パターンの純粋な踏襲*。

**影響箇所**: `WorktreeMeta` を直接構築している箇所（`save_worktree_display_name` 内 `main.rs:371-374` 相当、`migrate_worktree_meta` 内など）はすべて構造体リテラルで `display_name` のみをセットしているため、`parent` フィールド追加によりコンパイルエラーになる。各構築箇所に `parent: None`（または既存値を保持する場合は該当ロジック）を追加すること 🔵。

### 2. `save_worktree_parent` 関数（`src/config.rs`） 🟡

**信頼性**: 🟡 *architecture.md セクション2より。既存 `save_worktree_display_name`（`src/config.rs:355-383`）と同型のread-modify-writeパターンだが、`save_worktree_display_name` は「空値なら`meta.worktrees.remove()`でエントリ自体を削除する」という特殊仕様を持つため、`parent` 用に直接流用せず別ロジックとして実装する必要がある*

既存 `save_worktree_display_name`（`src/config.rs:355-383`）の実際のコードは以下の通り（実装前に必ずこの本体を読むこと）：

```rust
pub fn save_worktree_display_name(
    project_name: &str,
    worktree_name: &str,
    display_name: Option<&str>,
) -> Result<()> {
    let meta_path = project_meta_path(project_name);
    let mut meta = load_project_meta(project_name)
        .ok_or_else(|| anyhow::anyhow!("project.json が見つかりません: {}", project_name))?;
    let clean = display_name
        .map(crate::text::sanitize_text)
        .filter(|s| !s.is_empty());
    if let Some(name) = clean {
        meta.worktrees.insert(
            worktree_name.to_string(),
            WorktreeMeta { display_name: Some(name), .. },
        );
    } else {
        meta.worktrees.remove(worktree_name); // ⚠️ display_name専用の削除的挙動
    }
    let content = serde_json::to_string_pretty(&meta)?;
    std::fs::write(&meta_path, content)?;
    Ok(())
}
```

**重要な差異** 🔴: `save_worktree_display_name` は `None` を渡すと `meta.worktrees.remove(worktree_name)` で当該worktreeの `WorktreeMeta` エントリ**全体**を削除する（TASK-0006の親削除フックがこの関数を呼んでいるのはこのため）。`save_worktree_parent` に同じ「Noneならエントリごと削除」を適用すると、`parent=None` に設定したいだけで `display_name` 等の既存メタデータが消えてしまう副作用が生じるため、**`save_worktree_parent` は空値でもエントリを削除せず、`entry.parent = None` を代入するだけの実装にすること**（`entry().or_insert_with(WorktreeMeta::default)` パターンを推奨。そのためには `WorktreeMeta` に `#[derive(Default)]` を追加する必要がある 🟡）：

```rust
/// worktree の親リンクを設定する（REQ-012）。循環参照は呼び出し側(move_worktree等)で
/// 事前に would_create_cycle により検証すること。
/// 既存 save_worktree_display_name と異なり、parent=None でも WorktreeMeta エントリ自体は
/// 削除しない（display_name 等の既存メタデータを保持するため）。
pub fn save_worktree_parent(
    project_name: &str,
    worktree_name: &str,
    parent: Option<&str>,
) -> Result<()> {
    let meta_path = project_meta_path(project_name);
    let mut meta = load_project_meta(project_name)
        .ok_or_else(|| anyhow::anyhow!("project.json が見つかりません: {}", project_name))?;
    let entry = meta.worktrees.entry(worktree_name.to_string()).or_default();
    entry.parent = parent.map(|s| s.to_string());
    let content = serde_json::to_string_pretty(&meta)
        .context("project.json のシリアライズに失敗")?;
    std::fs::write(&meta_path, content)
        .with_context(|| format!("project.json の保存に失敗: {}", meta_path.display()))?;
    Ok(())
}
```

`WorktreeMeta::default()` を利用するため `#[derive(Default)]` を構造体に追加する（interfaces.rs でも `Default` 導出が明記されている）🔵 *interfaces.rs:38*。

### 3. `get_descendants` / `would_create_cycle`（`src/config.rs`） 🔵

**信頼性**: 🔵 *architecture.md セクション2の該当コードをそのまま転記、REQ-015, REQ-018*

既存資料に正確な実装が記載されているため、以下をほぼそのまま `config.rs` に追加する：

```rust
/// project_name 内で root_worktree の子孫（子・孫...）の名前一覧をDFSで返す（REQ-018）
pub fn get_descendants(project_name: &str, root_worktree: &str) -> Vec<String> {
    let Some(meta) = load_project_meta(project_name) else { return Vec::new() };
    let mut result = Vec::new();
    let mut stack = vec![root_worktree.to_string()];
    let mut visited = std::collections::HashSet::new(); // 🟡 防御的: データ破損時の無限ループ防止
    while let Some(current) = stack.pop() {
        for (name, wt_meta) in &meta.worktrees {
            if wt_meta.parent.as_deref() == Some(current.as_str()) && visited.insert(name.clone()) {
                result.push(name.clone());
                stack.push(name.clone());
            }
        }
    }
    result
}

/// 付け替え前の循環参照チェック（REQ-015）
/// new_parent が child 自身、または child の子孫である場合 true（付け替え禁止）
pub fn would_create_cycle(project_name: &str, child: &str, new_parent: &str) -> bool {
    new_parent == child || get_descendants(project_name, child).iter().any(|d| d == new_parent)
}
```

**注意点** 🟡: `get_descendants` はスタックへの `push` 順が `HashMap` イテレーション順（非決定的）に依存するため、返り値の**要素の集合**は決定的だが**順序**は決定的でない。DFS順であることを検証するテストは「順序を厳密比較」ではなく「A→B→Cのような直線的な親子チェーン」に限定するか、集合として比較すること（本タスクの単体テストの項を参照）。

## 基本的な単体テスト要件

**信頼性**: 🔵 *architecture.md該当コード + REQ-010, REQ-015, REQ-018より*

Given/When/Then形式で記述する。

### config.rs: 永続化の round-trip

- **Given**: 空の project.json（またはテスト用一時ディレクトリに新規作成した project）
- **When**: `save_worktree_parent(project, "child", Some("parent"))` を呼ぶ
- **Then**: `load_project_meta(project)` の `worktrees["child"].parent` が `Some("parent".to_string())` になっている

- **Given**: `parent` が既に `Some("A")` に設定済みのworktree
- **When**: `save_worktree_parent(project, "child", None)` を呼ぶ
- **Then**: `worktrees["child"]` エントリ自体は削除されず、`parent` のみ `None` になる（`display_name` 等の他フィールドが保持されている） 🔴 *`save_worktree_display_name` の削除的挙動との差異を保証する回帰テストとして重要度が高い*

### config.rs: `get_descendants`

- **Given**: 子を持たない単独worktree
- **When**: `get_descendants(project, "solo")` を呼ぶ
- **Then**: 空の `Vec` が返る

- **Given**: A(root) → B(parent=A) → C(parent=B) の3階層チェーン
- **When**: `get_descendants(project, "A")` を呼ぶ
- **Then**: 返り値の集合が `{"B", "C"}` と一致する（順序は問わない、上記「注意点」参照）

- **Given**: A→B, A→C（Aを共通の親に持つ兄弟）に加え、Aと無関係な独立worktree D
- **When**: `get_descendants(project, "A")` を呼ぶ
- **Then**: 返り値の集合が `{"B", "C"}` のみであり、`D` を含まない（ダイヤモンド型・無関係グラフでの誤包含がないこと）

### config.rs: `would_create_cycle`

- **Given**: 任意のworktree `X`
- **When**: `would_create_cycle(project, "X", "X")`（自己参照）を呼ぶ
- **Then**: `true` が返る

- **Given**: A(parent=None) ← B(parent=A) ← C(parent=B) という親子チェーン
- **When**: `would_create_cycle(project, "C", "A")`（Cの子孫にAはいないが、Aの祖先方向にCがいる = Cを親としてAに付け替えようとする循環）と `would_create_cycle(project, "A", "C")`（Aの子孫であるCをAの新しい親にしようとする、真の循環ケース）の両方を確認する
- **Then**: `would_create_cycle(project, "A", "C")` は `true`（CはAの子孫）、`would_create_cycle(project, "C", "A")` は `false`（AはCの子孫ではない）

- **Given**: 循環を含まない妥当な再割り当て（例: 独立worktree `D` を `A` の子にする）
- **When**: `would_create_cycle(project, "D", "A")` を呼ぶ
- **Then**: `false` が返る

### app.rs: `Worktree.parent` の配線確認

- **Given**: `parent: Some("A")` を持つ `WorktreeMeta` が保存された project.json
- **When**: `Project::from_config` でプロジェクトを読み込む
- **Then**: 該当 `Worktree.parent` が `Some("A".to_string())` になっている

- **Given**: 新規worktreeを `finalize_add_worktree` 経由で追加する
- **When**: 追加処理が完了する
- **Then**: 新規 `Worktree.parent` が `None` である

## タスク概要

TASK-0001/0002で実装済みの `dispatch` MCPツール（`target.type == "worktree"` のみ対応）を拡張し、`target.type == "subtree"` を受け付けて指定worktreeの子孫すべてへ一括dispatchできるようにする。子孫解決には TASK-0003 で実装済みの `config::get_descendants` を使う。あわせて `list_sessions` の `scope` に `"children"` を追加し、呼び出し元worktreeの子孫のセッションのみに絞り込めるようにする。

**設計上の要点** 🔵 *architecture.md セクション6より*: fan-out は MCPツール呼び出し時点（`messages` テーブルへのINSERTループ）でのみ発生し、TUI側の配送ロジック（TASK-0002で実装済みのTick処理）は一切変更しない。子孫1件=独立した `message_type='dispatch'` 行1行として扱われるため、TUI側は「1子=1行」を単純に繰り返し処理するだけでよい。これにより、ある子孫へのdispatchがPTY未生成でリトライ中でも、他の子孫への配送には一切影響しない（REQ-021）。

## 主要実装項目

### 1. `dispatch` の subtree アーム実装（`src/mcp/tools.rs`） 🔵

**信頼性**: 🔵 *mcp-tools.md「dispatch」実装概要より*

```rust
fn dispatch(conn: &Connection, params: &Value, from_session: &str) -> Result<Value> {
    let target = params.get("target").ok_or_else(|| anyhow::anyhow!("target is required"))?;
    let target_type = target.get("type").and_then(|v| v.as_str())
        .ok_or_else(|| anyhow::anyhow!("target.type is required"))?;
    let target_id = target.get("id").and_then(|v| v.as_str())
        .ok_or_else(|| anyhow::anyhow!("target.id is required"))?;
    let prompt = params.get("prompt").and_then(|v| v.as_str())
        .ok_or_else(|| anyhow::anyhow!("prompt is required"))?;

    // 呼び出し元セッションの project_name を自己解決（list_sessionsと同じ自己参照パターン）
    let all_sessions = db::list_sessions(conn)?;
    let project_name = all_sessions.iter()
        .find(|s| s.session_id == from_session)
        .map(|s| s.project_name.clone())
        .ok_or_else(|| anyhow::anyhow!("caller session not found"))?;

    let targets: Vec<String> = match target_type {
        "worktree" => vec![target_id.to_string()],
        "subtree" => config::get_descendants(&project_name, target_id), // REQ-017, REQ-018 ← 本タスクで実装
        _ => anyhow::bail!("Invalid target type: {}", target_type),
    };

    for wt_name in &targets {
        db::insert_message(
            conn, from_session, None, Some(wt_name), Some(&project_name),
            prompt, "dispatch", None,
        )?;
    }

    Ok(json!({ "dispatched": targets.len(), "targets": targets }))
}
```

**着目点** 🔵 *architecture.md セクション6より*:
- `"subtree"` の場合の `target_id` は「指揮者worktree名」（子孫のIDではない）
- 子孫が空Vecの場合、`for` ループが0回実行され、そのまま `{"dispatched": 0, "targets": []}` が返る。これは特別な分岐を要さず自然に成立する 🔵 *mcp-tools.md エラーケース欄より、意図された挙動*
- cross-project制約（EDGE-102）: `project_name` は常に呼び出し元セッション自身のprojectに固定されるため、`get_descendants` は自project内でのみ解決される。追加の防御コードは不要 🔵 *mcp-tools.md「cross-project制約」より*

### 2. `protocol.rs` のスキーマ確認・整合（`src/mcp/protocol.rs`） 🟡

**信頼性**: 🟡 *TASK-0001が並行実装中のため現状のスキーマ定義を本ラウンドで確認できていない。着手時に必ず実コードを確認すること*

`dispatch` ツールのスキーマは以下を宣言している前提（TASK-0001成果物）:

```json
"target": {
```

### 3. `list_sessions` の `"children"` scope アーム追加（`src/mcp/tools.rs`） 🔵

**信頼性**: 🔵 *mcp-tools.md「list_sessions の scope 拡張」の実装変更をそのまま採用*

既存の `match scope { "worktree" => .., "project" => .., _ => .. }` ブロック（`tools.rs:31-147` 付近、design-interview.md調査より）に以下のアームを追加する:

```rust
"children" => all_sessions.iter()
    .filter(|s| {
        !proj.is_empty() && s.project_name == proj
            && config::get_descendants(proj, wt).contains(&s.worktree_name)
    })
    .collect(),
```

`proj`/`wt` は呼び出し元セッションから自己解決した `project_name`/`worktree_name`（既存の `"worktree"` scopeアームで使っている変数をそのまま再利用する）🔵 *mcp-tools.md記載コードをそのまま踏襲*。

**呼び出し元自身の除外について** 🔵 *mcp-tools.md「戻り値」節・architecture.mdセクション6より*: `get_descendants(proj, wt)` は `wt` 自身を含まない（子孫のみを返す、`config.rs`のDFS実装がrootを結果に含めない設計のため）。したがって呼び出し元自身のセッションは `descendants.contains(&s.worktree_name)` が `false` となり自動的に除外される。特別な除外ロジックの追加は不要。

## タスク概要

指揮者worktreeのClaudeが子worktreeへプロンプトを自動投入する仕組みの土台として、DB層に dispatch 専用の取得関数を追加し、MCPツール `dispatch` を新設する。あわせて、既存の保留メッセージ取得（`get_pending_messages`）から dispatch 行を除外し、SessionStart hook / `list_sessions` 経由の二重配信を防ぐ（REQ-007）。

本タスクは **DB層 + MCPツール層のみ**を対象とする。TUI本体（`main.rs`/`app.rs`/`terminal.rs`）側の実際のPTY書き込み・リトライ・アラートは [TASK-0002](TASK-0002.md) で実装する。`target.type` は `"worktree"` のみを実装対象とし、`"subtree"` は Phase 2（[TASK-0007](TASK-0007.md)）で有効化する 🔵 *requirements.md Phase 0 スコープ、mcp-tools.md「dispatch」入力スキーマ*。

## 主要実装項目

### 1. `DispatchRow` 型 + `get_pending_dispatches` 🔵

**信頼性**: 🔵 *interfaces.rs、architecture.md セクション1、実地確認 db.rs:378-385（既存 `MessageRow` の隣に配置）*

`src/db.rs` に以下を追加する。

```rust
/// dispatch専用の取得行（REQ-002）
/// 既存 MessageRow (db.rs:378-385) と同じ命名規則に揃えた新規struct
#[derive(Debug, Clone)]
pub struct DispatchRow {
    pub id: i64,                     // messages.id
    pub to_worktree: Option<String>, // messages.to_worktree（dispatchでは常にSomeのはずだが防御的にOption）
    pub to_project: Option<String>,  // messages.to_project（dispatch挿入時に必ずセットする、REQ-009/EDGE-102）
    pub content: String,             // messages.content = プロンプト本文
}

/// dispatch専用の未読メッセージを取得する（REQ-002）
/// 既存 get_pending_messages とは異なり、message_type='dispatch' のみを対象とする
pub fn get_pending_dispatches(conn: &Connection) -> Result<Vec<DispatchRow>> {
    let mut stmt = conn.prepare(
        "SELECT id, to_worktree, to_project, content
         FROM messages
         WHERE read_at IS NULL AND message_type = 'dispatch'
         ORDER BY created_at ASC",
    )?;
    let rows = stmt.query_map([], |row| {
        Ok(DispatchRow {
            id: row.get(0)?,
            to_worktree: row.get(1)?,
            to_project: row.get(2)?,
            content: row.get(3)?,
        })
    })?;
    let mut result = Vec::new();
    for row in rows {
        result.push(row?);
    }
    Ok(result)
}
```

既読化は**新規関数を追加しない**。既存の `mark_messages_read(conn: &Connection, message_ids: &[i64]) -> Result<()>`（実地確認: `db.rs:304-313`、id指定で `to_session` 条件なしに無条件更新）をそのまま再利用する 🔵 *design-interview.md訂正より、dispatchは1行=1受信者のfanout設計のため無条件既読化で安全*。

> **実装メモ** 🔵: `mcp-tools.md` の実装例コメントは戻り値を `Result<usize>` と記載しているが、実地確認の結果、現行実装は `Result<()>`（マッチ件数を返さない）である。呼び出し側（TASK-0002のTick処理）はこの戻り値を無視して構わない（`let _ = db::mark_messages_read(...)`）。

```rust

 FROM messages

   AND (to_session = ?1
        OR to_worktree = ?2
```

### 3. `dispatch` MCPツールの JSON Schema（`src/mcp/protocol.rs`） 🔵

`tool_definitions()` の既存 `send_message`（`protocol.rs:79-97`）と同様の並びで、`dispatch` の `ToolDefinition` を追加する。

```rust
ToolDefinition {
    name: "dispatch".to_string(),
    description: "Send a prompt to a worktree's Claude terminal for fully-automatic injection (no human approval step, TUI Tick delivers it)".to_string(),
    input_schema: serde_json::json!({
```

> **実装メモ（本タスクのスコープ境界）** 🔵 *ユーザー指定の実装方針*: スキーマの `enum` には `"worktree"` と `"subtree"` を両方含めておいてよい（Phase 2 でのスキーマ変更を避けるため）。ただし本タスクで実装する `dispatch()` 関数のRust側 `match` は `"worktree"` アームのみ実装し、`"subtree"` は `_ => anyhow::bail!(...)` の一般 fallback に含めて明示的に失敗させる（下記4節参照）。これにより `"subtree"` を指定した呼び出しは [TASK-0007](TASK-0007.md) が `config::get_descendants` を配線するまで確実にエラーで止まり、サイレントな誤動作を防ぐ。

### 4. `dispatch` MCPツールの実装（`src/mcp/tools.rs`） 🔵

**信頼性**: 🔵 *mcp-tools.md「dispatch」実装概要、実地確認 tools.rs:10-29（`execute_tool`）, tools.rs:31-56（`list_sessions`の自己解決パターン）*

`execute_tool`（`tools.rs:10-29`）の `match tool_name` に新規アームを追加する。

```rust
pub fn execute_tool(
    conn: &Connection,
    tool_name: &str,
    params: &Value,
    session_id: &str,
) -> Result<Value> {
    match tool_name {
        "list_sessions" => list_sessions(conn, session_id, params),
        "send_message" => send_message(conn, params, session_id),
        "broadcast" => broadcast(conn, params, session_id),
        "set_summary" => set_summary(conn, params, session_id),
        "set_alert" => set_alert(conn, params, session_id),
        "handoff" => handoff(conn, params, session_id),
        "get_context" => get_context(conn, params),
        "save_skill" => save_skill(params),
        "list_skills" => list_skills(params),
        "summarize_history" => summarize_history(conn, params, session_id),
        "dispatch" => dispatch(conn, params, session_id), // 🔵 追加
        _ => anyhow::bail!("Unknown tool: {}", tool_name),
    }
}
```

`dispatch` 関数本体を新規実装する。呼び出し元の `project_name` 自己解決は、既存 `list_sessions`（`tools.rs:31-43`、`all_sessions.iter().find(|s| s.session_id == session_id)`）と同一パターンを踏襲する。

```rust
fn dispatch(conn: &Connection, params: &Value, from_session: &str) -> Result<Value> {
    let target = params.get("target").ok_or_else(|| anyhow::anyhow!("target is required"))?;
    let target_type = target.get("type").and_then(|v| v.as_str())
        .ok_or_else(|| anyhow::anyhow!("target.type is required"))?;
    let target_id = target.get("id").and_then(|v| v.as_str())
        .ok_or_else(|| anyhow::anyhow!("target.id is required"))?;
    let prompt = params.get("prompt").and_then(|v| v.as_str())
        .ok_or_else(|| anyhow::anyhow!("prompt is required"))?;

    // 呼び出し元セッションの project_name を自己解決（list_sessionsと同じ自己参照パターン、tools.rs:31-43）
    let all_sessions = db::list_sessions(conn)?;
    let project_name = all_sessions.iter()
        .find(|s| s.session_id == from_session)
        .map(|s| s.project_name.clone())
        .ok_or_else(|| anyhow::anyhow!("caller session not found"))?;

    let targets: Vec<String> = match target_type {
        "worktree" => vec![target_id.to_string()],
        // "subtree" は TASK-0007 で config::get_descendants を配線するまで未実装。
        // ここに含めず _ フォールバックで明示的にエラーとする（サイレントに worktree 扱いしない）。
        _ => anyhow::bail!("Invalid or not-yet-supported target type: {}", target_type),
    };

    for wt_name in &targets {
        db::insert_message(
            conn, from_session, None, Some(wt_name), Some(&project_name),
            prompt, "dispatch", None,                                    // REQ-001, REQ-007
        )?;
    }

    Ok(json!({ "dispatched": targets.len(), "targets": targets }))
}
```

**REQ-008/NFR-101（人間承認なしの完全自動投入）** 🔵 *design-interview.md訂正1*: `dispatch` は同期的にDB INSERTするのみで、承認ステップを一切設けない。ワーカー側の危険ツール実行のゲートは siki の `PreToolUse` hook（`src/hooks.rs:36-47`、`is_async: true` のセッション状態通知専用）ではなく、Claude Code CLI 自体の組み込み権限承認システムが担う。本タスクはこの安全境界に影響を与えない（DB層・MCP層のみでPTYに直接触れない）。

**REQ-009（tab0固定）** 🔵: 本タスクではDB行に `to_worktree`/`to_project` のみを記録し、tab番号は保持しない。「常にtab0へ投入する」という制約は TASK-0002 のTUI配送側（`claude_terms.get_mut(&(wt_id, 0))`）で保証されるため、本タスクのスコープでは対応不要。

## 単体テスト要件

Given/When/Then 形式で以下を実装する（`src/db.rs` のテストモジュール、`src/mcp/tools.rs` のテストモジュールにそれぞれ追加）。

### `get_pending_dispatches` 🔵

- **Given** in-memory `Connection`（`Connection::open_in_memory()` + `db::init`相当のスキーマ適用）に `message_type='dispatch'` の未読行を1件、`message_type='message'` の未読行を1件INSERTした状態
  **When** `get_pending_dispatches(&conn)` を呼ぶ
  **Then** 戻り値の `Vec<DispatchRow>` の長さが1で、`message_type='dispatch'` の行のみが含まれる
- **Given** `message_type='dispatch'` かつ `read_at` が設定済み（既読）の行が1件ある状態
  **When** `get_pending_dispatches(&conn)` を呼ぶ
  **Then** 戻り値は空（既読行は含まれない）
- **Given** `message_type='dispatch'` の行を `created_at` の値をずらして複数件INSERTした状態
  **When** `get_pending_dispatches(&conn)` を呼ぶ
  **Then** 戻り値が `created_at` 昇順に並んでいる

### `get_pending_messages`（回帰） 🔵

- **Given** 同一 `to_worktree`/`to_project` 宛に `message_type='dispatch'` の行と `message_type='message'` の行が両方ある状態
  **When** `get_pending_messages(&conn, session_id, worktree, project)` を呼ぶ
  **Then** 戻り値に `message_type='dispatch'` の行が含まれない（`message_type='message'` の行のみ返る）

### `dispatch()` ツール 🔵

- **Given** 呼び出し元セッションが `list_sessions` から解決可能で、`target: {type:"worktree", id:"child-a"}`, `prompt:"do X"` を渡す
  **When** `dispatch(&conn, &params, from_session)` を呼ぶ
  **Then** `messages` テーブルに `message_type='dispatch'`, `to_worktree='child-a'`, `to_project=<呼び出し元project>`, `content='do X'` の行が1件INSERTされ、戻り値が `{"dispatched":1,"targets":["child-a"]}` と一致する
- **Given** `target.type` が `"subtree"` または未知の文字列（例: `"invalid"`）
  **When** `dispatch(...)` を呼ぶ
  **Then** `Err` が返り、メッセージに `Invalid or not-yet-supported target type` を含む（`"subtree"` はTASK-0007まで意図的にエラーとする）
- **Given** `params` に `target` キーが存在しない、または `prompt` キーが存在しない
  **When** `dispatch(...)` を呼ぶ
  **Then** `Err` が返る（`target is required` / `prompt is required` 相当）
- **Given** `from_session` が `list_sessions` の結果に存在しない未知のセッションID
  **When** `dispatch(...)` を呼ぶ
  **Then** `Err`（`caller session not found`）が返る

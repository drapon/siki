## タスク概要

`src/ui/left_panel.rs` の既存バッジ描画ロジック（現状は `session_registry` の `aggregate_state`/`has_alert` を `(project_name, &wt.name)` のみに対して呼び、そのworktree自身のセッション状態だけを表示している）を拡張し、親worktreeのバッジに子孫worktreeの状態をロールアップ表示する。TASK-0003で実装済みの `config::get_descendants` を使って子孫一覧を取得し、各子孫に対して**既存の** `SessionRegistry::aggregate_state`/`has_alert`（`session.rs`側は無変更）を呼び出し、状態は `priority()` による `max_by_key` で、アラートはブール値のORで、それぞれ自分自身の状態・アラートと畳み込む。

**回帰安全性が最重要** 🔵 *完了条件・design-interview.md訂正6より*: 子を持たないworktree（既存利用のほぼ全て）に対しては `get_descendants` が空Vecを返し、ロールアップ処理が実質no-opとなり、変更前と完全に同一のバッジが描画されなければならない。この左ペインバッジ計算は siki 内で最も頻繁にヒットする描画パスの一つであるため、回帰テストを必須とする。

## 主要実装項目

### 1. バッジ計算部への子孫ロールアップ追加（`src/ui/left_panel.rs`） 🔵

**信頼性**: 🔵 *architecture.md セクション6のコード例より、そのまま適用可能*

```rust
// ui/left_panel.rs のバッジ計算部（既存: session_registry から (project_name, &wt.name) の
// aggregate_state/has_alert を呼んでいる箇所）に追加する
let descendants = config::get_descendants(project_name, &wt.name); // 子がいなければ空Vec 🔵
let subtree_state = descendants.iter()
    .filter_map(|d| session_registry.and_then(|r| r.aggregate_state(project_name, d)))
    .max_by_key(|s| s.priority());
let subtree_alert = descendants.iter()
    .any(|d| session_registry.map(|r| r.has_alert(project_name, d)).unwrap_or(false));

// 最終的なバッジ状態 = 自分自身の状態/アラートと subtree_state/subtree_alert の優先度マージ
let own_state = session_registry.and_then(|r| r.aggregate_state(project_name, &wt.name));
let own_alert = session_registry.map(|r| r.has_alert(project_name, &wt.name)).unwrap_or(false);

let merged_state = [own_state, subtree_state]
    .into_iter()
    .flatten()
    .max_by_key(|s| s.priority()); // 🔵 状態は優先度によるmax畳み込み
let merged_alert = own_alert || subtree_alert; // 🔵 アラートはOR畳み込み
```

**既存メソッドは無変更で再利用する** 🔵 *design-interview.md訂正6より*: `SessionRegistry::aggregate_state`/`has_alert` は `(project_name, worktree_name)` の文字列ペアで全件線形走査するO(n)実装であり、子孫名の集合に対して繰り返し呼び出すだけでロールアップが成立する。新規インデックス構造・新規メソッドの追加は不要。

**no-opの保証** 🔵 *完了条件・NFR-201「既存の罫線・インデント表現規約を踏襲」より*: `descendants` が空Vecの場合、`filter_map`/`any` はいずれもイテレーション0回で完了し、`subtree_state = None`, `subtree_alert = false` となる。この場合 `merged_state == own_state`, `merged_alert == own_alert` となり、変更前の計算結果と完全に一致する。この性質自体が本タスクの回帰安全性の根拠である。

### 2. 優先度比較の前提確認（`priority()` メソッド） 🟡

**信頼性**: 🟡 *architecture.mdのコード例で `s.priority()` が前提とされているが、状態型・`priority()`メソッドの正確な定義箇所は本ラウンドで直接確認できていない*

`aggregate_state` の戻り値型（おそらく既存の状態enum、例えば `SessionState` 相当）に `priority()` メソッドが既に定義されている前提でコード例が書かれている。実装着手時に `src/session.rs` を確認し、以下を検証すること:
- `priority()` が既存メソッドとして存在するか（存在すれば流用、存在しなければ本タスクで最小限追加する）
- 状態の優先順位（例: alert相当の状態 > working > idle など）が「子の方が優先度が高い状態であれば親に反映される」という直感と一致するか

### 3. 呼び出し箇所の確認（既存バッジ描画フローとの統合） 🟡

**信頼性**: 🟡 *architecture.md記載のコード片は挿入位置の目安のみで、`left_panel.rs`の関数名・シグネチャは本ラウンドで未特定*

`left_panel.rs` 内の既存バッジ計算箇所（`session_registry` を参照して `(project_name, &wt.name)` のみでバッジ状態を決めている関数、おそらく描画関数内のローカルロジックまたは専用ヘルパー関数）を特定し、そこに上記ロールアップを差し込む。関数の切り出し方針（既存関数内にインライン追加するか、`compute_badge_state` 等の小関数へ抽出するか）はコーディングスタイル規約（1関数50行未満、単一責任）に従い実装時に判断する 🟡。

## 基本的なテスト要件

### 単体テスト: 子なしworktreeの回帰確認（最重要） 🔵

**信頼性**: 🔵 *完了条件・回帰安全性の要求より、本タスクで最も優先度の高いテスト*

- 子を持たない（`parent`リンクが誰からも参照されていない）worktreeについて、本変更前のバッジ計算結果（`own_state`/`own_alert` のみを使った既存ロジックの出力）と、本変更後の `merged_state`/`merged_alert` が完全に一致することを確認する
- 具体的には、複数の `own_state`（idle/working/アラート状態それぞれ）パターンについてこの一致を確認し、単一ケースのみで済ませない

### 単体テスト: ロールアップ優先度の正しさ 🔵

**信頼性**: 🔵 *完了条件より*

- 親自身が `idle`、子2件のうち1件が `working` の場合、`merged_state` が `working` 優先度になることを確認する
- 親自身が `working`、すべての子が `idle` の場合、`merged_state` が親自身の `working` のまま変わらないことを確認する（子の状態が親の状態を「格下げ」しないことの確認）

### 単体テスト: アラートOR畳み込みの正しさ 🔵

**信頼性**: 🔵 *完了条件より*

- 親にアラートなし・子1件にアラートありの場合、`merged_alert == true` になることを確認する
- 親・子いずれにもアラートがない場合、`merged_alert == false` のままであることを確認する

### 単体テスト: 多階層（孫）ロールアップの推移性 🔵

**信頼性**: 🔵 *完了条件・TASK-0003の `get_descendants` DFS実装（再帰的に子孫を辿る）が本ロールアップにも正しく波及することの確認*

- A→B→C（Cの親がB、Bの親がA）の3階層構成で、Cにのみアラートがある場合、`get_descendants(project, "A")` が `["B", "C"]` を返すこと、およびAのバッジ計算で `merged_alert == true` になることを確認する（直接の子Bだけを見て孫Cを見落とさないことの確認）
- 同様の3階層構成でCのみが `working` 状態の場合、Aのバッジが `working` 優先度にロールアップされることを確認する

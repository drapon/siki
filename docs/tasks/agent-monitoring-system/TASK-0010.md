## タスク概要

実装した監視機能を、テストコードではなく実機（siki TUI を起動し、複数 worktree で Claude Code を実際に動かす）で総合検証する DIRECT タスク。プロジェクト別ポップアップ（`m`）と全体ダッシュボード（`M`）が、エージェントのツール実行に追従してリアルタイムに activity を表示し、alert/waiting 行が赤強調され、ソート・経過時間・省略・スクロール・クローズ・ヘルプ記載が要件どおり機能することを目視で確認する。

あわせて `cargo build` / `cargo test` を実行して全体のグリーン（exit 0・failures 0）を確認し、既存機能（左ペインのバッジ・既存キーバインド）に回帰がないことを確かめる。検証はエビデンス（実行ログ・目視結果メモ）を残す。

## 実装詳細（検証手順）

### 1. 全体ビルド・テスト 🔵

**信頼性レベル**: 🔵 *verification ルール（実行結果で判断）/ acceptance-criteria 全体*

`cargo build` と `cargo test` を実行し、**それぞれの出力**から exit 0・failures 0 を確認する。失敗があれば本タスクを完了とせず、原因に応じて前段タスクへ戻す。

### 2. siki 起動と2ビューの起動（REQ-003/004） 🔵

**信頼性レベル**: 🔵 *REQ-003/004 / dataflow.md 機能2・3*

siki を起動し、複数 worktree で Claude Code を稼働させた状態で、左ペインから `m`（カーソル位置プロジェクトのポップアップ）と `M`（Shift+m, 全体ダッシュボード）を開く。worktree 行にカーソルがある状態で `m` を押し、所属プロジェクトに解決されること（REQ-106）も合わせて確認する。

### 3. activity のリアルタイム反映（REQ-001/002/101, NFR-001） 🔵

**信頼性レベル**: 🔵 *REQ-001/002/101 / NFR-001 / dataflow.md システム全体フロー*

エージェントがツールを実行すると、対応する activity（例「Bash: …」「Edit: …」）が、ユーザー操作なしにビュー表示中へリアルタイム（1 秒未満, NFR-001）で反映されることを目視確認する。複数 worktree で同時に動かし、それぞれの行が独立に更新されることを確認する。

### 4. alert/waiting 行の赤強調（REQ-104） 🔵

**信頼性レベル**: 🔵 *REQ-104 / session.rs alert 判定*

許可待ち（waiting）や `set_alert` で alert が立ったセッション行が、赤系の配色で強調表示されることを確認する。alert 解消後に強調が外れることも確認する。

### 5. ソート・表示項目・操作の確認（REQ-005/006, REQ-301, REQ-105, NFR-201） 🔵

**信頼性レベル**: 🔵 *REQ-005/006/105/301 / NFR-201 / dataflow.md 機能3*

ダッシュボードで状態優先順ソート（waiting > working > done > idle, REQ-006）が効くこと、各行に activity・summary・role・state・経過時間が表示されること（REQ-005）、長文が `…` で省略されること、`j`/`k` スクロールで全件閲覧できること（REQ-301）、`Esc` で閉じること（REQ-105）を確認する。`?`/`F1` のヘルプに `m`/`M`/`Esc` が記載されていること（NFR-201）も確認する。

### 6. 既存機能の回帰確認 🔵

**信頼性レベル**: 🔵 *REQ-401（後方互換）/ 既存 UI への加算的変更方針*

左ペインのバッジ（●/○）や既存のキーバインドが従来どおり動作し、新ビューの追加で回帰していないことを確認する。従来形式（activity なし）の working イベントも引き続き受理されること（REQ-401）を、必要に応じて確認する。

## UI/UX要件

- 状態変化から監視ビューへの反映が体感で 1 秒未満（NFR-001）。
- alert/waiting 行が赤系で視認しやすく強調（REQ-104）。
- 各行に経過時間が表示され、長文は `…` で省略され行崩れしない（NFR-202）。
- `j`/`k` スクロールと `Esc` クローズが直感的に機能し、TUI 全体の応答性を損なわない（NFR-002）。

## 実装手順（DIRECT）

1. **direct-setup**: 検証環境を整える。`cargo build` で実行バイナリを用意し、hook が注入された複数 worktree と broker 稼働を確認。siki を起動し、複数 worktree で Claude Code を動かせる状態にする。
2. **direct-verify**: 上記「実装詳細（検証手順）」1〜6 を順に実施。`cargo build`/`cargo test` の出力（exit code・failures 件数）と、各ビューの目視結果を記録する。acceptance-criteria の主要 TC を1件ずつ突き合わせ、合否とエビデンス（ログ抜粋・観察メモ）を残す。

## 注意事項

- DIRECT タスク（direct-setup → direct-verify の2フェーズ）。コードの作り込みは前段タスクで完了している前提で、本タスクは「実機で要件どおり動くか」の確認に集中する。
- verification ルールに従い、**実行結果（cargo の実出力・目視結果）で判断**する。「通るはず」「反映されるはず」で完了としない。
- `cargo test` / `cargo build` は今回のメッセージ内で実際に実行し、出力の failures 件数（0）と exit code（0）を読んでから完了を主張する。
- 不具合・要件未達を見つけた場合は本タスクを完了とせず、該当する前段タスク（TASK-0004〜0009）へ差し戻す。
- 検証は破壊的操作を伴わない範囲で行い、実 DB（SQLite）やローカル状態を不用意に汚さないよう注意する（NFR-101: ローカル完結・外部送信なし）。

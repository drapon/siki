## タスク概要

監視ビューの入口となるキー操作と描画分岐を実装する。`src/main.rs` の左ペインのキーディスパッチに `m`（カーソル位置から所属プロジェクトを解決して `show_agent_popup` をオン）と `M`（Shift+m、`show_agent_dashboard` をオン）を追加し、これらのポップアップ表示中は他ペインのキーを早期 return で横取りして `Esc` で閉じ、`j`/`k`（または ↑/↓）で対応する `*_scroll` を増減する。`src/ui/mod.rs` の `render()` に両ポップアップの描画分岐を追加し、ヘルプ（`?`/F1）テキストに `m`/`M`/`Esc` を追記する。🔵 *dataflow.md 機能2/3 / 既存 show_* キー処理・render 分岐*

## 実装詳細

### 1. `m`: カーソル→所属プロジェクト解決してポップアップ起動

- 信頼性レベル: 🔵
- 出典: `dataflow.md` 機能2 ステップ1-2、REQ-106、既存 `src/main.rs` 左ペインのキーディスパッチ
- 実装ファイル: `src/main.rs`（解決ロジックは関数化して `src/app.rs` 等に置くと単体テストしやすい）

```rust
// カーソル位置（左ペイン）→ 所属プロジェクト index を解決
// worktree 行でも、その worktree が属する project の index を返す（REQ-106）
fn resolve_project_index(app: &App) -> Option<usize> { /* ... */ }

// main.rs 左ペインのキー処理（既存ディスパッチに追加）
KeyCode::Char('m') => {
    if let Some(idx) = resolve_project_index(app) {
        app.agent_popup_project_index = idx;
        app.agent_popup_scroll = 0;
        app.show_agent_popup = true;
    }
}
```

### 3. 表示中のキー横取り（Esc クローズ / j/k スクロール）

- 信頼性レベル: 🔵
- 出典: REQ-105 / REQ-201 / REQ-301、既存ポップアップの「表示中は早期 return で横取り」パターン
- 実装ファイル: `src/main.rs`

```rust
// 他ペインのキー処理より前で、表示中なら横取りして早期 return する
if app.show_agent_popup {
    match key.code {
        KeyCode::Esc => { app.show_agent_popup = false; }
        KeyCode::Char('j') | KeyCode::Down => {
            app.agent_popup_scroll = app.agent_popup_scroll.saturating_add(1);
        }
        KeyCode::Char('k') | KeyCode::Up => {
            app.agent_popup_scroll = app.agent_popup_scroll.saturating_sub(1);
        }
        _ => {}
    }
    return; // 他ペインへ伝播させない（REQ-201）
}
if app.show_agent_dashboard {
    match key.code {
        KeyCode::Esc => { app.show_agent_dashboard = false; }
        KeyCode::Char('j') | KeyCode::Down => {
            app.agent_dashboard_scroll = app.agent_dashboard_scroll.saturating_add(1);
        }
        KeyCode::Char('k') | KeyCode::Up => {
            app.agent_dashboard_scroll = app.agent_dashboard_scroll.saturating_sub(1);
        }
        _ => {}
    }
    return;
}
```

## 単体テスト要件

純粋ロジックは `#[cfg(test)] mod tests` に実テストを書き、`cargo test` で検証する。

### カーソル→プロジェクト解決 `resolve_project_index`

- Given: カーソルがプロジェクト行にある / カーソルがある worktree 行にある App
- When: `resolve_project_index(app)` を呼ぶ
- Then: いずれの場合も、その行が属するプロジェクトの index を返す（worktree 行でも所属プロジェクトに解決, REQ-106）

### スクロール境界クランプ

- Given: `agent_popup_scroll == 0` で `k` 相当の減算を行う / 大きな値で `j` 相当の加算を行う
- When: `saturating_sub(1)` / `saturating_add(1)` を適用する
- Then: 0 未満にならない（0 に留まる）/ オーバーフローしない（必要なら描画側で行数に応じて上限クランプする）

```rust
#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn resolve_project_from_worktree_row() {
        // worktree 行カーソルでも所属 project の index を返す
    }

    #[test]
    fn scroll_clamps_at_zero() {
        assert_eq!(0usize.saturating_sub(1), 0);
    }
}
```

（描画側で「スクロール上限 = 行数 - 表示行数」にクランプする場合は、そのクランプ関数も純粋関数として単体テストする。）

## UI/UX要件

- **スクロール**: `j`/`k`（または ↑/↓）で `*_scroll` を増減。下限 0 でクランプ（REQ-201/REQ-301）。
- **Esc クローズ**: 表示中の `Esc` で対応ビューを閉じ通常画面へ戻す（REQ-105）。
- **発見可能性**: ヘルプに `m`/`M`/`Esc`/`j`/`k` を明記（NFR-201）。
- 経過時間・赤強調・省略・空表示そのものは TASK-0006/0007 の描画関数が担当（本タスクはトリガーと分岐のみ）。

## 注意事項

- 既存キー（Enter / A / a / Space / i / g 等）と**衝突しない**こと。`m`/`M` が左ペインで未使用であることを実装前に確認する。
- `M` の登録位置（グローバル or 左ペイン）は `src/main.rs` の既存ディスパッチ構造に合わせる。横取り判定（show_agent_popup / show_agent_dashboard）は他ペインのキー処理より**前**に置く。
- 表示中の早期 return を入れることで、スクロールキーなどが背後のペインに漏れないようにする（既存ポップアップと同様）。
- スクロール上限クランプは描画側（行数を知る場所）で行うのが自然。キー側では `saturating_*` で下限のみ担保する。
- イミュータビリティ方針: App の状態更新はプロジェクトの既存スタイル（直接代入か新インスタンス返却か）に合わせる。

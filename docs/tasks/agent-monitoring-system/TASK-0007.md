### 1. render_agent_dashboard 本体（枠とレイアウト）

- 信頼性レベル: 🔵

- 実装ファイル: `src/ui/mod.rs`

```rust
// src/ui/mod.rs
pub fn render_agent_dashboard(frame: &mut Frame, app: &App, registry: &SessionRegistry) {
    let area = centered_rect(80, 80, frame.area());
    frame.render_widget(Clear, area);
    let block = Block::default()
        .title(" Agents (all) ")
        .borders(Borders::ALL);
    let inner = block.inner(area);
    frame.render_widget(block, area);
    // all() → AgentRow → ソート → スクロール窓 → 描画（下記 2〜4）
}
```

### 2. all() 全セッションの AgentRow 化（unknown を含む）

- 信頼性レベル: 🔵
- 出典: `dataflow.md` 機能3 ステップ2、EDGE-003（`unknown/unknown` も表示）、`all()` アクセサ
- 実装ファイル: `src/ui/mod.rs`

```rust
let now = std::time::Instant::now();
let mut rows: Vec<AgentRow> = registry.all().map(|s| AgentRow {
    project_name: s.project_name.clone(),   // 空でも unknown として扱い除外しない
    worktree_name: s.worktree_name.clone(),
    role: s.role.clone(),
    state: s.state,
    activity: s.activity.clone(),
    summary: s.summary.clone(),
    elapsed_secs: now.duration_since(s.last_seen).as_secs(),
    alert: s.alert,
}).collect();
```

### 3. 状態優先順ソート

- 信頼性レベル: 🔵
- 出典: REQ-006、interfaces.rs `dashboard_sort_key`、既存 `SessionState::priority()`（Waiting4 > Working3 > Done2 > Idle1）
- 実装ファイル: `src/ui/mod.rs`

```rust
fn dashboard_sort_key(row: &AgentRow) -> (std::cmp::Reverse<u8>, String, String) {
    (
        std::cmp::Reverse(row.state.priority()),
        row.project_name.clone(),
        row.worktree_name.clone(),
    )
}

rows.sort_by_key(dashboard_sort_key);
// priority 降順 → 同状態は project 名昇順 → worktree 名昇順
```

## 単体テスト要件

ソートは純粋関数なので `#[cfg(test)] mod tests` に実テストを書き、`cargo test` で検証する。描画は `TestBackend` で最低限のスモーク（任意）。

### 状態優先順ソート

- Given: Idle / Working / Waiting / Done が混在し、同状態に複数 project/worktree がある `AgentRow` の配列
- When: `dashboard_sort_key` で `sort_by_key` する
- Then: 並び順が waiting → working → done → idle、同状態内では project 名昇順、さらに worktree 名昇順になる

### unknown 行の非除外

- Given: `project_name` / `worktree_name` が `"unknown"`（または空）の `AgentRow` を含む配列
- When: ダッシュボード行構築（all() マッピング + ソート）を行う
- Then: unknown 行が結果から除外されない（件数が維持され、unknown 行が含まれる）

## UI/UX要件

- **赤強調**: `is_attention`（alert または Waiting）が true の行を赤系で強調（REQ-104）。
- **長文の省略（…）**: activity / summary を幅に応じて末尾 `…` で省略（EDGE-102）。
- **経過時間表示**: 各行に経過時間を `format_elapsed` 形式で表示（REQ-005）。
- **スクロール**: `agent_dashboard_scroll` を起点にスクロール窓を適用（REQ-301）。
- 全セッションを横断表示するため、TASK-0006 のポップアップより広い `centered_rect(80, 80)` を用いる。

## 注意事項

- TASK-0006 の `AgentRow` / `format_elapsed` / `truncate_ellipsis` / `is_attention` を**共有**する（重複実装しない）。本タスクで新たに作るのは `dashboard_sort_key` と `render_agent_dashboard` のみ。
- `registry.all()` の結果から `unknown/unknown` を**除外しない**（EDGE-003）。フィルタを掛けないこと。
- `SessionRegistry` はライブ参照（`&SessionRegistry`）で受け取り、コピーを保持しない。
- `priority()` は既存の Waiting4 > Working3 > Done2 > Idle1。`Reverse` で降順にする点に注意（priority が大きいほど上に来る）。
- イミュータビリティ方針に従い、ソートはローカルに collect した `Vec` に対して行う。

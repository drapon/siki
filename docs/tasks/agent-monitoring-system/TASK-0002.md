## タスク概要

状態モデルに activity を載せる。`HookEvent::Working` に `#[serde(default)] activity: Option<String>` を追加して後方互換を保ち、`Session` 構造体に `pub activity: Option<String>` を追加する。`handle_event(Working)` で activity が `Some` のときのみ `Session.activity` を更新し、それ以外の遷移（idle / waiting / refresh）では**直前の activity を保持**する（REQ-103）。`Dead` は従来どおりセッションごと削除する。

### 3. handle_event(Working) での activity 反映 🔵

**信頼性レベル**: 🔵 *REQ-102 / REQ-103 / 既存 `src/session.rs:342,352`*

**実装ファイル**: `src/session.rs`

```rust
HookEvent::Working { session_id, activity } => {
    // 未登録なら既存ロジックで自動登録（unknown 紐付け）
    // activity が Some のときのみ更新。None や他遷移では直前を保持（REQ-103）。
    if let Some(a) = activity {
        if let Some(s) = self.sessions.get_mut(&session_id) {
            s.activity = Some(a);
        }
    }
    self.update_state(&session_id, SessionState::Working);
    true
}
```

他の `Idle` / `Waiting` / `Refresh` アームは activity に触れない（保持）。`Dead` は既存どおりセッション削除。

- 既存テストの `HookEvent::Working { session_id: .. }` 生成箇所（例: `src/session.rs:589`）をフィールド追加に追従修正する（`activity: None` を補う、または `..` は構築では使えないため明示）。

## 実装詳細

### reindex_project_maps 新設 🔵

**信頼性**: 🔵 *architecture.md「データモデル（Rust型定義）」より*

**実装ファイル**: `src/main.rs`

```rust
/// プロジェクト削除後、削除位置より後ろの project_index を持つ
/// sessions / terminals / claude_terms のキーを1つ前にずらす
fn reindex_project_maps(
    sessions: &mut HashMap<app::WorktreeId, claude::ClaudeSession>,
    terminals: &mut HashMap<TerminalKey, terminal::TerminalEmulator>,
    claude_terms: &mut HashMap<(app::WorktreeId, usize), terminal::TerminalEmulator>,
    removed_project_index: usize,
) {
    let keys: Vec<_> = sessions
        .keys()
        .filter(|(pi, _)| *pi > removed_project_index)
        .cloned()
        .collect();
    for (pi, wi) in keys {
        if let Some(val) = sessions.remove(&(pi, wi)) {
            sessions.insert((pi - 1, wi), val);
        }
    }

    let keys: Vec<_> = terminals
        .keys()
        .filter(|((pi, _), _)| *pi > removed_project_index)
        .cloned()
        .collect();
    for ((pi, wi), tab) in keys {
        if let Some(val) = terminals.remove(&((pi, wi), tab)) {
            terminals.insert(((pi - 1, wi), tab), val);
        }
    }

    let keys: Vec<_> = claude_terms
        .keys()
        .filter(|((pi, _), _)| *pi > removed_project_index)
        .cloned()
        .collect();
    for ((pi, wi), tab) in keys {
        if let Some(val) = claude_terms.remove(&((pi, wi), tab)) {
            claude_terms.insert(((pi - 1, wi), tab), val);
        }
    }
}
```

## 単体テスト要件

### テストケース1: 3マップすべてでproject_indexが正しくシフトする 🔵

**信頼性**: 🔵 *requirements.md TC-101-01より*

**Given**: `sessions`/`terminals`/`claude_terms` に `project_index=2` のキーを持つエントリが
それぞれ存在する（`project_index=0,1` のエントリも混在させる）
**When**: `reindex_project_maps(&mut sessions, &mut terminals, &mut claude_terms, 1)` を呼ぶ
（project_index=1のプロジェクトを削除した想定）
**Then**: `project_index=2` だったエントリはすべて `project_index=1` のキーに移動しており、
`project_index=0` だったエントリは変化しない

**テストファイル**: `src/main.rs`（既存 `mod tests` 内、`test_remove_worktree` 等と同様の
パターンで追加）

### テストケース2: 末尾プロジェクト削除時はシフト対象なし（境界値） 🔵

**信頼性**: 🔵 *requirements.md EDGE-101・TC-101-B02より*

**Given**: `project_index=0,1` のエントリのみ存在する状態
**When**: `reindex_project_maps(..., removed_project_index=1)` を呼ぶ（末尾を削除した想定）
**Then**: どのエントリも移動しない（シフト対象となる `project_index > 1` のキーが
存在しないため）

### テストケース3: プロジェクトが1件のみの状態での削除（境界値） 🔵

**信頼性**: 🔵 *requirements.md EDGE-102・TC-101-B01より*

**Given**: `project_index=0` のエントリのみ存在する状態
**When**: `reindex_project_maps(..., removed_project_index=0)` を呼ぶ
**Then**: 各マップは変化せず、パニックも発生せず正常終了する

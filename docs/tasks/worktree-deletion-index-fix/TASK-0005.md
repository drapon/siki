## タスク概要

`sessions` 用の `resolve_session_key` を新設し、`AppEvent::ClaudeOutput`/`ClaudeComplete`/
`ClaudeError` の処理（`main.rs:654-690,710-715`）を、イベントの生の `worktree_id` ではなく
「`session_id` 一致で解決した現在のキー」で `app.worktree_by_id_mut`/`app.worktree_by_id`
を呼ぶよう書き換える。これにより、worktree削除後にシフトしたキー位置へ別の実在worktreeが
来ていても誤って書き込まれなくなる（Bug B 解消）。

## 実装詳細

### resolve_session_key 新設 🔵

**信頼性**: 🔵 *architecture.md「データモデル（Rust型定義）」より*

**実装ファイル**: `src/main.rs`

```rust
/// sessions 用の id ベース再解決ヘルパー
/// REQ-006: 見つかった「現在のキー」を worktree 特定に用いる
/// （イベントの古い worktree_id は worktree 特定に直接使わない）
fn resolve_session_key(
    sessions: &HashMap<app::WorktreeId, claude::ClaudeSession>,
    worktree_id: app::WorktreeId,
    session_id: u64,
) -> Option<app::WorktreeId> {
    if let Some(session) = sessions.get(&worktree_id) {
        if session.id() == session_id {
            return Some(worktree_id);
        }
    }
    sessions
        .iter()
        .find(|(_, session)| session.id() == session_id)
        .map(|(key, _)| *key)
}
```

### イベントハンドラの書き換え 🔵

**信頼性**: 🔵 *dataflow.md「修正後のフロー（Bug B 解消）」より*

**実装ファイル**: `src/main.rs:654-690,710-715`

```rust
// 変更前:
// AppEvent::ClaudeOutput { worktree_id, event: ref stream_event } => {
//     ...
//     app.handle_claude_output(worktree_id, stream_event.clone());
// }

// 変更後:
AppEvent::ClaudeOutput { worktree_id, session_id, event: ref stream_event } => {
    if let Some(key) = resolve_session_key(sessions, worktree_id, session_id) {
        // 既存の Init イベント時のDB更新処理は key（解決済み）で worktree を特定する
        app.handle_claude_output(key, stream_event.clone());
    }
    // 解決できない場合は何もしない（REQ-401: 黙って破棄）
}
```

`ClaudeComplete`/`ClaudeError` も同様に、`resolve_session_key` で解決したキーを
`app.handle_claude_complete`/`app.handle_claude_error` に渡す。

> **注意**: `handle_claude_output` 内の Init イベント処理（DB更新、`main.rs:658-680`）は
> worktree 名を取得するために `app.worktree_by_id(worktree_id)` を呼んでいる。ここも
> 解決済みキー `key` を使うよう合わせて修正する。

**信頼性**: 🔵 *requirements.md TC-002-01より*

**Then**: `Some((pi,1))` が返る（`(pi,2)` ではない）

（reindex未発生の通常状態）

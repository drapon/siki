## タスク概要

`ClaudeSession`（`claude.rs`）に、`TerminalEmulator::id`（既存）と同様の生成時点で採番される
グローバル一意 `id: u64` を追加する。採番カウンタは `claude.rs` 内に独立した
`NEXT_SESSION_ID: AtomicU64` として新設する（`terminal.rs::NEXT_TERMINAL_ID` とは共有しない、
design-interview.md Q2で決定）。

## 依存タスク

- **前提タスク**: なし（起点）
- **後続タスク**: [TASK-0004](TASK-0004.md)

## 完了条件

- [ ] `claude.rs` に `static NEXT_SESSION_ID: AtomicU64 = AtomicU64::new(1);` を追加
- [ ] `ClaudeSession` に `id: u64` フィールドを追加
- [ ] `ClaudeSession::id(&self) -> u64` アクセサを追加（`TerminalEmulator::id()` と同形）
- [ ] `ClaudeSession::spawn` 内で `NEXT_SESSION_ID.fetch_add(1, Ordering::Relaxed)` により
      採番し `id` フィールドに設定する
- [ ] 同一プロセス内で複数回 `spawn` した場合に異なる `id` が採番されることを検証する
      ユニットテストを追加する
- [ ] `cargo build`/`cargo test` が通る（この時点では `id` はまだイベントに乗らない。
      TASK-0004で配線する）

## 実装詳細

### NEXT_SESSION_ID とフィールド追加 🔵

**信頼性**: 🔵 *architecture.md「データモデル（Rust型定義）」より*

**実装ファイル**: `src/claude.rs`

```rust
use std::sync::atomic::{AtomicU64, Ordering};

/// ClaudeSession のグローバル一意id採番用カウンタ
/// terminal.rs::NEXT_TERMINAL_ID とは独立（design-interview.md Q2）
static NEXT_SESSION_ID: AtomicU64 = AtomicU64::new(1);

pub struct ClaudeSession {
    id: u64, // 新規フィールド。生成時点で不変の一意id
    worktree_id: WorktreeId,
    // ...既存フィールド（変更なし）
}

impl ClaudeSession {
    /// 生存期間中不変の一意id
    pub fn id(&self) -> u64 {
        self.id
    }

    pub async fn spawn(
        path: &Path,
        event_tx: mpsc::UnboundedSender<AppEvent>,
        worktree_id: WorktreeId,
        resume_id: Option<&str>,
    ) -> Result<Self> {
        let id = NEXT_SESSION_ID.fetch_add(1, Ordering::Relaxed);
        // ...既存の起動処理（プロセス起動・stdin/stdoutハンドル取得等）は変更しない
        Ok(Self {
            id,
            worktree_id,
            // ...既存フィールド初期化
        })
    }
}
```
